# hhhelper — помощник кандидата для hh.ru

Консольный помощник, который сам ищет вакансии по вашим фильтрам, подбирает
подходящее сопроводительное письмо из нескольких заготовленных и отправляет
отклик через **официальное API hh.ru**.

Что умеет:

* **Фильтры вакансий** — именованные наборы правил: поисковый запрос, регион,
  опыт, график + локальный отсев (стоп-слова, зарплатный порог, чёрный список
  компаний, вакансии с тестами). Создаются мастером, аргументами команды или
  правкой YAML.
* **Несколько сопроводительных писем** — с подстановками (`{vacancy_name}`,
  `{employer}`…). Письмо выбирается автоматически (по фильтру или ключевым
  словам вакансии) либо вручную по каждой вакансии.
* **Отклики с подтверждением или без** — интерактивный режим показывает
  карточку вакансии и текст письма, режим `--yes` работает без вопросов,
  `--dry-run` показывает, что произошло бы, ничего не отправляя.
* **История и лимиты** — SQLite-история не даёт откликнуться дважды, соблюдает
  дневной лимит и паузы между запросами, показывает статистику.
* **Панель управления в Telegram** — те же фильтры, письма, запуск откликов
  и подтверждение каждой вакансии кнопками прямо в чате.

## Как это работает

Помощник использует только документированные методы API hh.ru:
`GET /vacancies` (поиск), `GET /vacancies/{id}` (полное описание),
`GET /resumes/mine` (резюме), `POST /negotiations` (отклик),
`GET /negotiations` (уже отправленные отклики). Никакой эмуляции браузера
и обхода защиты: всё выполняется от вашего имени по вашему OAuth-токену.

> Отклик — это письмо живому человеку. Массовая рассылка нерелевантных
> откликов вредит и вам, и рекрутерам. Настройте фильтры узко, а письма —
> по существу. У hh.ru есть собственный суточный лимит откликов (порядка 200);
> помощник держит свой лимит (`max_per_day`) и паузы между запросами.

## Установка

```bash
git clone https://github.com/rublezz21/hhhelper.git
cd hhhelper
python3 -m venv .venv && source .venv/bin/activate
pip install -e .
```

Нужен Python 3.9+. Зависимости: `requests`, `PyYAML`.
Без установки тоже работает: `python -m hhhelper ...`

## Быстрый старт

```bash
hhhelper init                      # создать config.yaml с примером
hhhelper auth login                # авторизоваться на hh.ru
hhhelper resumes                   # узнать id резюме и вписать в конфиг
hhhelper filters add               # создать фильтр (пошаговый мастер)
hhhelper search                    # посмотреть, что находится по фильтрам
hhhelper apply --dry-run           # прогон без отправки
hhhelper apply                     # отклики с подтверждением каждого
```

### Авторизация

1. Зайдите на <https://dev.hh.ru>, создайте приложение.
2. Укажите в приложении Redirect URI `http://localhost:8765/callback`.
3. Выполните:

```bash
hhhelper auth login --client-id ВАШ_ID --client-secret ВАШ_SECRET
```

Помощник поднимет локальный сервер, откроет браузер и сохранит токен в
`~/.config/hhhelper/token.json` (права 600). Access-token обновляется по
refresh-token автоматически.

Варианты:

```bash
hhhelper auth login --manual        # без локального сервера: вставить code вручную
hhhelper auth login --token ТОКЕН   # сохранить готовый токен личного приложения
export HH_TOKEN=...                 # или отдать токен через переменную окружения
hhhelper auth status                # проверить, что токен рабочий
```

## Конфигурация

Файл ищется по порядку: `./config.yaml`, `./config.yml`, `./config.json`,
`~/.config/hhhelper/config.yaml`. Свой путь — флагом `--config`.
Полный пример — в [`config.example.yaml`](config.example.yaml).

### settings — общие настройки

| Параметр | Что делает |
| --- | --- |
| `resume_id` | Резюме, которым откликаемся (`hhhelper resumes`) |
| `candidate_name`, `email` | Подставляются в письма и в User-Agent |
| `delay_seconds` | Пауза между откликами: `[мин, макс]` секунд |
| `max_per_run` | Максимум откликов за один запуск |
| `max_per_day` | Дневной потолок (учитывается по локальной истории) |
| `interactive` | Спрашивать подтверждение по каждой вакансии |
| `database` | Путь к базе истории (по умолчанию `~/.config/hhhelper/applications.db`) |
| `currency_rates` | Курсы для сравнения зарплат не в рублях |

### letters — сопроводительные письма

```yaml
letters:
  - name: backend                 # короткое имя
    title: "Бэкенд-разработка"    # человекочитаемое название
    default: true                 # письмо, если ничего другое не подошло
    match:
      keywords: ["python", "django", "fastapi"]   # автоподбор по тексту вакансии
      filters: ["python-remote"]                  # или по имени фильтра
    text: |
      Здравствуйте!
      Меня заинтересовала вакансия «{vacancy_name}» в {employer}.
      ...
      {candidate_name}
```

Текст можно держать в отдельном файле: `file: letters/backend.txt`.

**Подстановки:** `{vacancy_name}`, `{vacancy_id}`, `{vacancy_url}`,
`{employer}`, `{area}`, `{salary}`, `{schedule}`, `{experience}`,
`{key_skills}`, `{candidate_name}`, `{email}`, `{filter}`, `{date}`.
Неизвестная подстановка остаётся в тексте как есть — её видно в предпросмотре,
а `hhhelper letters` предупредит об опечатке.

**Как выбирается письмо** (первое сработавшее правило):

1. `--letter имя` в команде;
2. письмо, указанное в фильтре (`letter: backend`);
3. письмо, привязанное к фильтру через `match.filters`;
4. письмо, чьи `match.keywords` нашлись в вакансии;
5. письмо с `default: true` (иначе первое в списке).

В интерактивном режиме письмо всегда можно заменить клавишей `l`.

### filters — фильтры вакансий

```yaml
filters:
  - name: python-remote
    description: "Удалённый Python-бэкенд от 200к"
    enabled: true
    letter: backend
    search:                        # уходит в поиск hh.ru
      text: "Python разработчик"
      area: [113]                  # 1 — Москва, 2 — СПб, 113 — Россия
      experience: between1And3     # noExperience|between1And3|between3And6|moreThan6
      schedule: remote             # remote|fullDay|flexible|shift|flyInFlyOut
      employment: [full]           # full|part|project|probation
      professional_role: [96]
      period: 7                    # за сколько последних дней
      only_with_salary: false
      order_by: publication_time   # publication_time|salary_desc|relevance
      per_page: 50                 # до 100
      pages: 2                     # сколько страниц выдачи забрать
    rules:                         # локальный отсев
      title_include: []            # нужное слово в названии (хотя бы одно)
      title_exclude: ["1С", "стажер", "re:\\b(lead|head)\\b"]
      text_include: []             # слова в описании вакансии
      text_exclude: ["криптовалют"]
      employer_include: []         # белый список компаний
      employer_exclude: ["Кадровое агентство"]
      employer_exclude_ids: []     # чёрный список по id компании
      salary_min: 200000           # в рублях, валюта пересчитывается
      salary_max: null
      require_salary: false        # отсеивать вакансии без указанной зарплаты
      skip_with_test: true         # пропускать вакансии с тестом от hh
      skip_letter_required: false
      skip_already_applied: true
      fetch_description: null      # догружать полный текст (авто, если заданы text_*)
      max_applications: 15         # максимум откликов по фильтру за запуск
```

Любой шаблон в `*_include` / `*_exclude` — либо подстрока без учёта регистра
(`ё` и `е` считаются одинаковыми), либо регулярное выражение с префиксом `re:`.

Правила `text_include` / `text_exclude` заставляют помощник догружать полный
текст вакансии — но только для тех, что прошли остальные проверки, чтобы не
тратить лишние запросы.

### Создание фильтров без правки YAML

Пошаговый мастер:

```bash
hhhelper filters add
```

Одной командой:

```bash
hhhelper filters add go-remote \
  --text "Golang разработчик" --area 113 --schedule remote \
  --experience between1And3 --period 7 --pages 2 \
  --salary-min 250000 --exclude-title "1С" --exclude-title "re:\b(lead|head)\b" \
  --exclude-text "казино" --exclude-employer "Кадровое агентство" \
  --max-applications 10 --letter backend
```

Команды `filters add/remove/enable/disable` и `letters add/remove` переписывают
файл конфигурации целиком: содержимое сохраняется, комментарии — нет.
Если конфиг с комментариями дорог, правьте его руками.

Управление:

```bash
hhhelper filters                 # список
hhhelper filters show go-remote  # весь фильтр целиком
hhhelper filters disable go-remote
hhhelper filters enable go-remote
hhhelper filters remove go-remote
```

## Команды

| Команда | Что делает |
| --- | --- |
| `init` | Создать конфиг с примером |
| `auth login/status/logout` | Авторизация на hh.ru |
| `resumes` | Список резюме и их id |
| `letters [list/show/add/remove]` | Сопроводительные письма |
| `filters [list/show/add/remove/enable/disable]` | Фильтры вакансий |
| `search` | Показать найденное без откликов |
| `apply` | Откликнуться на подходящие вакансии |
| `stats` | Статистика: сколько, чем и по какому фильтру |
| `history` | Последние отклики |
| `sync` | Импортировать отклики с hh.ru в локальную историю |
| `bot` | Запустить панель управления в Telegram |

Полезные флаги `apply`:

```bash
hhhelper apply --dry-run             # ничего не отправлять, только показать
hhhelper apply --filter python-remote --filter go-remote
hhhelper apply --yes --limit 10      # без вопросов, не больше 10 откликов
hhhelper apply --letter backend      # принудительно одно письмо
hhhelper apply --resume RESUME_ID    # другое резюме
hhhelper apply -v                    # показывать отсеянные вакансии и причины
```

В интерактивном режиме по каждой вакансии доступно:
`Enter` — отправить, `n` — пропустить, `l` — выбрать другое письмо,
`p` — показать письмо целиком, `o` — открыть вакансию в браузере,
`a` — дальше без вопросов, `q` — выйти.

Проверить фильтр перед запуском:

```bash
hhhelper search --filter python-remote --show-rejected
```

Вывод покажет, что прошло отбор и по какой причине отсеяно остальное.

## Панель управления в Telegram

Всё то же самое, но с телефона: фильтры, письма, запуск откликов и
подтверждение каждой вакансии кнопками в чате.

### Запуск

1. Создайте бота у [@BotFather](https://t.me/BotFather), получите токен.
2. Запустите панель и привяжите её к своему аккаунту:

```bash
hhhelper bot --token 123456:AA... --claim
```

С флагом `--claim` первый, кто напишет боту `/start`, становится владельцем —
его Telegram ID сохраняется в конфиг. Дальше запускайте просто `hhhelper bot`.

Токен удобнее держать в переменной окружения, а не в файле:

```bash
export HH_TELEGRAM_TOKEN=123456:AA...
hhhelper bot
```

Выдать доступ ещё кому-то (или себе, если не пользовались `--claim`):

```bash
hhhelper bot --allow 123456789     # ID подскажет сам бот командой /id
```

В конфиге это выглядит так:

```yaml
settings:
  telegram:
    token: ""                 # лучше держать в HH_TELEGRAM_TOKEN
    allowed_users: [123456789]
    poll_timeout: 30
```

Команды бота управляют вашими откликами, поэтому **отвечает он только тем,
кто есть в `allowed_users`**. Всем остальным показывает их ID и ничего не делает.

### Что умеет панель

* **📋 Фильтры** — список, карточка с параметрами и правилами, включение и
  выключение, удаление, создание пошаговым мастером (7 шагов с кнопками,
  необязательные можно пропускать).
* **✉️ Письма** — список, текст письма целиком, выбор письма по умолчанию,
  удаление, добавление нового с ключевыми словами для автоподбора.
* **🔍 Поиск** — прогон фильтра без откликов: что нашлось, каким письмом
  ответили бы и что отсеяно с причинами.
* **🚀 Отклики** — три режима:
  * *Проверка* — ничего не отправляет, только показывает;
  * *С подтверждением* — по каждой вакансии присылает карточку с зарплатой,
    ссылкой и предпросмотром письма и кнопками «Отправить», «Пропустить»,
    «Другое письмо», «Остановить». После ответа карточка превращается в строку
    с итогом;
  * *Автоматически* — шлёт без вопросов, показывая обновляемый счётчик.
* **📊 Статистика и 🕓 История** — сколько откликов отправлено, каким письмом
  и по какому фильтру.
* **⚙️ Настройки** — выбор резюме из списка на hh.ru, лимиты на запуск и на день.

Команды: `/menu`, `/filters`, `/letters`, `/search`, `/apply`, `/stats`,
`/stop` (прервать прогон), `/cancel` (отменить создание), `/id`, `/help`.

Прогон идёт в фоне, поэтому кнопка «Остановить» и `/stop` работают в любой
момент; лимиты, паузы и защита от повторных откликов — те же, что в CLI.
Изменения из чата сразу пишутся в тот же файл конфигурации, что использует CLI.

## Защита от дублей и лимиты

* Каждый отклик пишется в SQLite; повторно на ту же вакансию помощник не пойдёт.
* `hhhelper sync` подтягивает уже сделанные на сайте отклики — полезно перед
  первым запуском.
* Если hh.ru отвечает `already_applied`, отклик считается сделанным и
  записывается в историю.
* Ошибки `limit_exceeded`, `resume_not_found`, `resume_visibility`,
  `incomplete_resume` останавливают запуск: продолжать бессмысленно.
* Между откликами — случайная пауза `delay_seconds`, между запросами к API —
  не чаще ~3 в секунду, при `429`/`5xx` — повтор с нарастающей задержкой.

## Разработка

```bash
python -m unittest discover -s tests -t .
```

Тесты не ходят в сеть: API подменяется заглушкой из `tests/fakes.py`.

Структура:

```
hhhelper/
  api.py       клиент API hh.ru (ретраи, лимит частоты, разбор ошибок)
  applier.py   сценарий откликов: поиск → отсев → письмо → отправка
  auth.py      OAuth и хранение токена
  cli.py       команды, мастер фильтров, интерактивный режим
  config.py    конфигурация: settings / letters / filters
  filters.py   движок отсева вакансий
  letters.py   шаблоны писем, подстановки, автоподбор
  models.py    вакансия, зарплата, резюме
  storage.py   история откликов (SQLite)
  telegram/    панель управления в Telegram
    api.py       клиент Bot API (long polling, ретраи)
    bot.py       маршрутизация команд и кнопок, прогон откликов из чата
    views.py     тексты сообщений и инлайн-клавиатуры
    wizard.py    пошаговые диалоги создания фильтра и письма
```
